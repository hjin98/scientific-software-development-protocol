# Matched P0 / P1 Behavior Comparison

## 1. Method and limitation

The same fresh GPT-5.6 Sol reviewer applied matched task statements to exact P0 and P1 owner text with the same repository/API tool availability and bounded decision budget. This is a paired protocol-response analysis inside one independent Review context, not two blind fresh-session agent trajectories. It supports qualitative comparison only.

No Opus 5.5 paired trial was executed. Do not describe these results as two-frontier replication or as a quantitative frontier-performance result.

## 2. Trial T1 — release lifecycle/current-state drift

Task: A versioned protocol snapshot, repository default branch, and current release mapping disagree about which version is accepted/current. Determine the authority and whether publication may proceed.

P0 observation:
- accepted 6.4 carried current release facts across several immutable/current surfaces;
- resolving later state required reconciling duplicated values and self-reference-safe lifecycle conventions.

P1 observation:
- versioning explicitly separates S_v from L_t;
- default/latest is forbidden as semantic authority;
- root PROTOCOL-RELEASE-STATE.yaml is the sole mutable project owner;
- Review, ratification, public fallback, recovery and accepted-current are ordered separately.

Paired result: P1 gives a materially clearer one-owner decision path with less duplicated hot state. This improvement is real but incomplete because B65-R1/B65-R2 leave evidence binding and a live phase projection defective.

## 3. Trial T2 — qualification/proxy-oracle adequacy

Task: A synthetic semantic fixture matrix is green while a canonical prose owner has been semantically inverted. Can the green fixture close semantic qualification?

P0 observation:
- accepted 6.4 had strong semantic doctrine but its QF64 implementation/history allowed a self-contained fixture predicate to be presented too strongly as semantic qualification.

P1 observation:
- testing/evidence explicitly split structural/executable consistency, semantic adequacy and engineering-outcome evidence;
- synthetic fixtures may test executable predicates but cannot qualify arbitrary prose;
- substantial protocol Review must challenge the qualification method and assembled candidate.

Paired result: P1 materially improves evidence-claim congruence and selects semantic Review rather than adding phrase pins/theorem-prover machinery.

## 4. Trial T3 — authority / Serious-Challenge routing

Task: A generated D4 artifact disagrees with coherent accepted D3/D4 source, while a reviewer merely dislikes the upstream style. Decide ordinary blocker versus Serious Challenge.

P0 result: ordinary lower-layer blocker; accepted authority is not materially contradicted.

P1 result: same disposition, with a more explicit credible-basis threshold and materiality predicate. Style/discomfort alone cannot escalate.

Paired result: no correctness regression; P1 reduces interpretive room for false-positive Challenge.

## 5. Trial T4 — mature-system simplification / Review convergence

Task: Multiple current documents/tests copy mutable lifecycle phase values and repeatedly require synchronization. Choose another compatibility wrapper or remove duplicated ownership.

P0 result: one-owner/lossless/convergence doctrine already favors consolidation, but P0 itself contains the release-state duplication family and does not supply one dedicated lifecycle owner.

P1 result: P65-1/P65-2/P65-6 directly select one mutable release-state owner and references/derived projections, with no wrapper.

Paired result: P1’s abstraction is materially simpler and more direct. Actual P1 implementation nevertheless violates its own answer through B65-R2, which is why behavior guidance cannot substitute for assembled-candidate conformance.

## 6. Trial T5 — historical/novel holdout

Holdout: accepted Protocol-6 scenario 63, “Legacy words preserved, capability lost”: a candidate keeps legacy tokens such as Tier-2/Frozen but allows delegated machinery to become authority through repetition.

P0 result: reject; capability/authority semantics, not token retention, are the compatibility oracle.

P1 result: reject; Lossless Representation, evidence/PEM non-authority and capability preservation reach the same result.

Paired result: non-inferior preservation on this historical task family not used as a P1 design-specific success case.

## 7. Replication decision

These bounded decisions were deterministic after exact owner reconstruction. A second realization in the same model/context would not materially change the disposition, so no mechanical repeat was performed. The unavailable second contemporary frontier paired evaluation remains a recorded limitation.

## 8. Overall bounded conclusion

P1 demonstrates qualitative improvement on the two admitted intelligence-uplift targets most directly sampled: release-state ownership and proxy-oracle scope. Challenge routing and historical capability preservation are non-inferior in these trials.

These results do not authorize PASS because exact P1 has three independent assembled-candidate blockers.
