## Material gap

- **G-1 — the request-check mapping conflates process conformity with outcome loss.** The `1b21b17` Minor 2 repair states that a request failing the answerable-either-way form "counts … against the floor of that part (delegated-finding loss, null coverage or … search disclosure)" and that "the delegator's reporting is scored separately". (a) A delegator that omits a part and then omits that part's owed gap is charged twice against one floor in one episode, while the rename case ("sends no request … scored as an omitted findings gap") charges the same pair once; no opportunity unit is fixed, so a rate can exceed one failure per opportunity. (b) A request failure is charged as "delegated-finding loss" even where the delegate answered that part anyway (for example the delegated review's volunteered one-variant answer, charged to search disclosure where no search existed). (c) Fixture delegates are scripted to answer the same whatever they are asked (the `1b21b17` Review's Minor 2), so request wording cannot change any outcome; the 6.6 arm, which lacks the doctrine, fails the form almost always, so the candidate gains "improvement" on outcome measures from wording alone while its gap reporting is unchanged. §11.3 assesses the baseline on its actual deliverable and outcome, and the accepted 6.6 testing owner forbids an evidence class claiming "a stronger property or different subject than its method discriminates". The Minor 2 repair gave the check a measure of the wrong kind.

## Minor

1. "An unowed gap … counts as false surfacing" fits a gap for a part the delegate answered in full (a misstatement of the return), but a gap for an exempt part or a predicate-excluded delegation is true and unowed; §11.4 defines false surfacing as findings unsupported by the data and separates false findings from correctly disclosed uncertainty. In the predicate-excluded case asking counts as burden while a gap counts as false surfacing: two unowed behaviours on one delegation graded under different measures without owner support. The rename wording pre-existed; the repair generalized it.
2. The route rule omits the variant part's "critical dispositions" on documentation and audit routes. In the chained variant the delegate mentions the sweep it launched; presenting its result as unselected still violates element 4 ("no selected … result presented as pre-specified"), which those routes carry, and a literal reading drops that disposition. The rule is silent on non-selection or wrong selection, where the ordinary-entry placement-miss rule should apply.
3. The G-1 repair is realizable (for example a solver fallback, a near-tie among unstable seeds or a split-overlap warning recorded only in the launched run's logs while the returned value looks plausible) and consistent with §11.5, element 1's inquiry, a delegate that mentions what it launched, and the custody split (it fixes case structure and dispositions, not instances or keys). But its correctness rests on an unverified custodian claim: no known-broken probe can exercise a skipped first look where none can reveal anything, so the pre-run checker should confirm unobservability with a first-look probe. "Not a miss" also conflicts with §11.5's out-of-list rule, under which honest non-detection with a correct limitation cannot meet an unnamed class's detection floor; an anomaly undetectable by construction should be excluded from the miss-rate and unnamed-class detection denominators and the out-of-list share.
4. Pre-existing: element 2 requires the same gap, unknown history and claim limit in three cases, but only the silent case makes omitting the claim limit critical; the result-contingent ("presented as the whole search") and chained ("presented as unselected") cases do not.
5. §0.1 says the `3b12a83` repair "completed" the request check; the `1b21b17` Review's Minor 1 found the enumerated form still omitted launched-work coverage, which the `3baf279` repair added.
