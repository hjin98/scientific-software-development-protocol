Governing SSDP 6.6.0; Protocol 7.0 NON-QUALIFIED. ## Scope and protected invariant

This document owns only the verification witness for decision item 8 and D4 case (z), “no byte-identical copy ... in any encoding,” and the whole-owner-line source exclusion of item 6. It preserves the ledger mechanism, allowed capabilities, heartbeat/window rules, accounting and campaign rules. It adds no runtime principal or communication edge. It does not replace the independent executor rehearsal.

An **alternate package source** is sandbox-reachable retained data or executable content from which the subject can reconstruct an installed package file without opening the watched installed package, irrespective of the representation (including an owner-only copy, an archive, Git objects, or a computation using an embedded key). Ordinary model knowledge without a sandbox-reachable source is outside this filesystem/input premise. The intended prohibition includes owner-only copies; copying all package files is not required to violate it. Authorized catalog/root delivery and supplied content arising from watched reads are accounted input/output paths, not hidden alternate sources.

## Verification witness: closed frozen-source provenance

“In any encoding” prohibits alternate sources in every representation; it does not prescribe enumeration of all decoders or require deciding arbitrary programs. The checker verifies a **closed construction/provenance witness** for the complete executor-reachable initial and externally supplied input surface. This is a sufficient constructive witness, rather than a claim that a substring or decoder scan proves a universal negative.

The witness binds the exact package tree and owner, fixture/workspace, task text, runtime/control/dependency trees, catalog/delivery transformation, stub/MCP input and result-producing code, and every other permitted external input source. It enumerates regular-file bytes and symlink targets, sandbox mount destinations and source identities. Unlisted sources, additional mounts, escaping symlinks, or externally supplied values outside that closure make the premise **UNRESOLVED**, never PASS. The independent checker reports the source envelope and its completeness warrant.

Each non-package source is either (a) an independently reviewed, immutable seed with a retained provenance/inspection record warranting that it contains neither an alternate package source nor a whole owner line at the floor, or (b) the output of an explicitly identified construction from such seeds. Construction records bind input/output hashes and the reviewed generator/transformation. **Every construction edge and output requires its own retained semantic exclusion-preservation warrant for the actual inputs, operation and output; a reviewed generator identity or absence of an installed-package import does not establish preservation. The jointly reachable source envelope also requires a retained exclusion warrant: separately clean fragments, keys, decoders or generators may compose into an alternate source.** The graph must close at those seeds; it may not import the installed package into an alternate source, conceal an input, or rely on the author's PASS label. Runtime binaries, executable fixtures and generated tool-result sources are seeds/constructions too: their origin is not exempt merely because a file looks like software. Unknown, unreviewable, undecidable or otherwise unproved origins, transformations, outputs or composition fail closed. The independent checker's acceptance record, substantive warrants and exact bindings are part of the evidence; mechanically checking hashes verifies a reviewed witness, not the truth of an unreviewed attestation.

Generated subject workspace content may depend on the closed initial sources and watched package reads. The containment/input owner must demonstrate that no other input path exists; supplied outside data must have its own frozen source witness. This preserves process execution while preventing unchecked input channels. A change to a source, generator, package, mount layout, task or external-input envelope invalidates the witness and requires regeneration and independent checking before a ledger profile is admitted. A package regeneration always requires a fresh witness, even if a previous package had no collisions.

The mechanical tool verifies exact witness coverage/bindings, construction graph closure, source/member byte identities, one package bind, no hard links, symlink containment, and whole-owner-line collisions across every non-owner source in the frozen envelope. Known decoder/archive/Git inspection is additional falsification: finding a reconstructed package file rejects the witness. Failure to find one cannot establish witness closure. No finite decoder list narrows the prohibited encodings. A misleading or false reviewed witness is an evidence/acceptance failure and reopens its real owner, not a reason to silently trust a hash match.

## Outcomes, ownership and retained records

- **PASS:** complete mechanically checked witness plus independently accepted seed/construction/containment inspection, all identities current, no demonstrated premise violation.
- **FAIL:** demonstrated alternate source, whole-owner-line collision, extra package bind or hard link; retain the counterexample.
- **UNRESOLVED:** missing/incomplete/unverified/stale witness or any origin, source, transformation or input boundary whose closure cannot be established. No negative owner conclusion or exact byte claim may be admitted from this profile until resolved. Positive owner evidence is retained and scored under revision 8, irrespective of premise loss; it is never suppressed.

The existing pre-run checker owns independent witness inspection and profile admission. The supervisor's tool performs mechanical verification before launch and retains its report with run evidence; evaluator/core verify its identities and bindings. D4 implements that tool and fail-closed integration; D4 cannot self-admit its reviewed seeds or the profile. Development/integrity tests may supply explicit known-construction fixtures and exercise the mechanical owner, but their witness status remains development-only and cannot be reused for qualification admission.

Retain the source/construct/mount manifest, inspection and acceptance records, mechanical report, per-source failure reasons, counterexamples and package/tree identities without rewriting earlier evidence. Reader: independent reviewer and pre-run checker. Routine questions: which source is covered, what constructive warrant excludes alternate package content, what changed, and why did the premise PASS/FAIL/remain UNRESOLVED? These inspectability surfaces are within the requested checker/evidence deliverable. No new scientific model, numerical method or realized scientific quantity is introduced.
