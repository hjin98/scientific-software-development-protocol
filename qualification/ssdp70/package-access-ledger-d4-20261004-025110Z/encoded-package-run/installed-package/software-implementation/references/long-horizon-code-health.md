# Long-Horizon Code Health and Autonomous Quality

Own longitudinal maintenance sensing, changed-surface quality ratchets, risk-triggered Verification, non-mutating Stabilization, and periodic Health Audit. This reference does not create product/scientific truth, approval roles, or numeric quality authority.

Generic evidence lifecycle is owned by [Evidence, evolution, and semantic dependencies](evidence-evolution-and-dependencies.md); test/oracle methods by [Testing and validation](testing-and-validation.md); recurrence/simplification by [Convergence and development-cycle economy](convergence-and-cycle-economy.md); universal Challenge/representation semantics by [Abstraction, concretization, authority, challenge, and representation](abstraction-and-concretization.md).

## Quality ratchet and sensors

Existing debt does not justify making a materially touched surface harder to reason about, more cyclic, more duplicated in authority, more weakly protected, or more dependent on exceptions without a governing reason. Capture only the task-local before-state needed for meaningful comparison; do not create a permanent health ledger solely for compliance.

Complexity/CRAP-like measures, churn, temporal change coupling, dependency centrality/cycles, duplication, coverage, mutation survival, public/configuration growth and related metrics are **sensors, not verdicts**. No universal threshold is normative. A useful heuristic is:

```text
maintenance risk ~ change frequency x structural complexity x test weakness x architectural centrality
```

Investigate the semantic cause and owning boundary before recommending change.

## Oracle/architecture health

For important changed decision logic, ask what plausible wrong behavior could still pass and route to the testing owner for appropriate counterfactual/property/differential/metamorphic/reference/real-owner evidence. Mutation survival is investigation evidence, not a required score.

Long-lived evidence must remain applicable to its current claim/candidate/oracle/regime/owner; route stale/remapped/retired decisions through the evidence owner rather than accumulating tests whose meaning no longer matches current authority.

Objective stable D3 rules such as dependency direction, acyclicity, independence, or absence/uniqueness of a retired owner may be executable when cheap and useful; do not build a universal architecture model for a score.

## Review and Verification

Independent Review reconstructs current authority, actual concretization, and material evidence applicability, then attempts falsification. Prefer fresh operational context for substantial/high-risk work when practical. Missing required implementation/acceptance evidence remains a blocker, not a reason to move it after Review.

**Verification** is a deeper optional risk-triggered falsification mode for materially high-risk scientific, numerical, architecture, or implementation claims. It may reconcile authorities, construct counterexamples, compare reference methods, inspect failure paths, or trace composed D4->D1 behavior. It is not a routine duplicate Review.

The universal Challenge rule applies: coherent child nonconformance is ordinary; evidence that accepted authority itself may be false, contradictory, materially ambiguous, inadequate, or impossible to concretize is a Serious Challenge routed to the earliest affected owner.

## Stabilization / architecture GC

At a material convergence boundary after ordinary Review otherwise passes, ask:

> If this concretization appeared fully formed today, would we deliberately choose it again for the same governing authority?

Inspect duplicate/synchronized representations, competing authorities, wrappers/adapters/fallbacks/special cases, stale compatibility, unnecessary state/config/public API, ownership leakage, dependency cycles, historical-exception conditionals, dead/bypassed paths, duplicated algorithms, stale evidence specifications, and tests dominated by internal orchestration rather than durable claims.

Stabilization is non-mutating. Required changes return through the normal owner: equivalent D4 simplification stays D4; architecture change reopens D3; numerical/scientific inadequacy routes to D2/D1.

A superseded implementation/test is ordinarily retireable only when it no longer owns/supports current authority, no supported current/compatibility path materially depends on it, and material historical rationale remains recoverable through Git/semantic evolution.

## Health Audit

Periodic Health Audit combines current semantic inspection with trustworthy available history: churn/change coupling, recurring defect families, complexity, dependency risk, public/config growth, test weakness, stale evidence and documentation difficulty. Do not fabricate trends from a static snapshot. Findings route work but do not mutate authority.

For persistence/restart/orchestration/cancellation/failure propagation, bounded deterministic fault injection may strengthen evidence while the real owner remains live; route detailed method to testing/tool/language owners. Prior realizations require applicability review when owner/candidate/regime changes.

## Closeout and representation

At substantial cycle/release completion reconcile affected current documentation, generated artifacts, semantic dependency/evolution records, evidence, completed/superseded workplan state and conservative repository hygiene. Closeout cannot archive semantics not yet consolidated into current owners.

Apply the Lossless Representation Rule to audits/reviews: consolidate manifestations under shared causes, lead with material deterioration/blockers, keep raw history cold unless needed to support a finding, and never convert compactness or a metric into a weaker acceptance standard.
