## Expected route classes and R2 route-probe reconciliation

Class **i**: §8.2 predicate excluded. Class **ii**: predicate applies but the task as given has no R2 owner-load step; the consumed clause suffices. Class **iii**: task as given calls for a consequential realized-result judgment, material D1–D3 authority work/acceptance Review, or human-gate evidence, so the owner is read before that step. These classify the *given route*, not every possible later trajectory. The custodian predeclares each case's observable R2 event; a developed task can change class on its trajectory and is adjudicated from that point. An unresolvable R2 event is unscorable, never a pass. This distinction preserves the 6.6 route map's expected/forbidden owner sets and adds only the Protocol 7 owner expectation: expect it for iii, forbid any pre-R2 read for i/ii. All other `routing-preservation-map.yaml` terms, positive/negative triggers, existing `expect` and `forbid` files, and paired P01–P19 floors remain unchanged.
