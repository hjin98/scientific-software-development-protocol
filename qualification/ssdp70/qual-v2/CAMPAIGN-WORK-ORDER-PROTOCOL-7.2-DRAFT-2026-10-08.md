## 1. What changed since the 7.1 requalification plan

The 7.1 plan (`PROTOCOL-7.1-REQUALIFICATION-PLAN.md`, superseded) relied on `requal71.py` for mechanical campaign gates. That module was retired in stage S2 (`eval/RETIRED-MODULES.md`). The consolidated tools are:

**What no longer exists mechanically (gaps; section 8):** corpus freshness against the disclosed material, custody-stat snapshots around custodian sessions, and a stratum-aware aggregate over runs. The builder from run directories to the `h4.py score` record now exists (`qual-v2/build_campaign_record.py`; section 8, item 4). `h4.py legacy` reads only the p71/p66 development runs. ## 12. Once-only format rerun of evaluator outputs (2026-10-10; seventh ruling; change control §8)

**Rule.** After the primary P9 pass, every assessment with status INVALID_SCHEMA or UNPARSEABLE is rerun once (`campaign_assess.py run ... --assessment-root <rerun root> --format-rerun-of <primary root>`), under a rerun root with a hash-bound `PASS-AUTHORIZATION.json` (phase `format-rerun`, `source_root`, `panels` equal to the run's `--panels`, frozen `runs: {slot: primary assessment.json sha256}`, driver/assessor/core/evidence/profile digests). The set is computed before the rerun from status alone (format-invalid) plus the mechanical transport or limit classification of EXECUTION_ERROR primaries (`transport_runs` and `limit_runs`, each `{slot: primary assessment-trace.jsonl sha256}`, disjoint subsets of `runs`). An exclusive `FORMAT-RERUN-STARTED.json` precedes any provider call, so a repeat is refused even if outputs are deleted. `collect --assessment-root <primary> --rerun-root <rerun>` takes a rerun result only for a frozen format-invalid, provider-transport or evaluator-limit primary (see the two extensions below) and only if that rerun is VALID. A second failure is unresolved and blocks qualification (no `--allow-unresolved` for a claim). Every other EXECUTION_ERROR, INADMISSIBLE and VALID assessment is never rerun.

**Operating-characteristic argument (§8; corrected after the independent review of 2026-10-10).** Thresholds, margins, exposures, populations, fixtures and the rubric are unchanged, so no gate's analytic characteristics are recomputed and no fresh blind fixtures are needed. What changes is the *guard*: today any unresolved item blocks a qualification claim (`build_campaign_record` refuses; `--allow-unresolved` is a waiver and `h4.score` then sets `valid_for_qualification=false`, `h4.py:269`; **no waiver is accepted for a claim**). The rerun therefore *relaxes* that conservative guard, making qualification more reachable; it must be justified on that basis, not as harmless.

(i) Selection. The rerun set is chosen by status and, for EXECUTION_ERROR, by the mechanical transport or limit classification (frozen before any rerun), identically for every arm, and the evaluator is blind to arm. The rule was adopted after a pilot whose four VALID records were all FAIL run outcomes; that does not make it verdict-selected (E037's own verdict is unknown), but it is recorded. (ii) Residual bias. A format failure on a field such as `critical` for `unauthorized_mutation` (which feeds Q4a-c) may be verdict-correlated and item-level, so the second draw can fail again; reruns would then mostly rescue benign items and leave a systematic, possibly arm-correlated residue, which stays unresolved and blocks. The recorded valid outputs are conditioned on format validity under either rule; a rerun does not remove that conditioning, and may add rescued items whose first draw was lost. (iii) Quantified expectation, assuming independent second draws (optimistic): with 441 sessions and first-draw failure rate f, P(no unresolved after one rerun) = (1-f²)^441 = 0.96 (f=1%), 0.84 (2%), 0.33 (5%), 0.012 (10%). Item-level correlation makes it worse. The only prior estimates: DeepSeek 23/441 INVALID_SCHEMA (5.2%) plus 2 UNPARSEABLE; MiMo pilot 1/5 (error-coverage slots, unrepresentative). So qualification stays reachable only if f is small (≲2-3%) and format failures are not item-systematic; otherwise the expected outcome is a blocked claim with a reported residue. (iv) Escalation. Any second-invalid (`reruns_second_invalid ≥ 1`) is returned to the stakeholder with the per-arm/panel/item/class report; no waiver, no further rerun and no normalization is applied. A first-draw failure rate above 10% is reported as evaluator inadequacy before any claim. C(b) (single-item path, 40 items, one invalid pair in attempt 2) is not an estimate of this rate.

**Scope notes.** UNPARSEABLE includes "no result text" with a zero exit; `collect` reports that subclass separately (it may mask a loop or cap) and the stakeholder may exclude it. Other EXECUTION_ERROR (a clean exit without a result, an unclassified failure), INADMISSIBLE and VALID assessments are not rerun by this path; the exceptions are a provider-transport EXECUTION_ERROR (*Transport extension*) and an evaluator wall-clock or turn-limit EXECUTION_ERROR (*Evaluator-limit extension*). **Retry policy:** an exception or harness/transport failure inside the rerun is not retried; that run stays unresolved (driver exit 3) and goes to the stakeholder. The tool validates keys, capabilities and rubric before creating the once-only marker.

**Reporting (`collect --rerun-root`).** Every collect and full-pass command for this campaign must pass `--assessment-root evaluations/mimo-1` (without a root, `collect` reads the superseded DeepSeek assessments in the run directories). A rerun that ended EXECUTION_ERROR/INADMISSIBLE is reported as such, never as a same-class format failure; missing/rejected reruns are counted. `format_failure_report`: first-draw format failures by arm, panel, status, error class and items named in schema errors; reruns attempted/valid/second-invalid, second-invalid by arm, same-class concordance, per-run rows. A rerun is accepted only with its marker, a matching authorization digest, and an `assessment-identity.json` equal to the primary's. The rerun set must equal every format-invalid primary plus every transport- or limit-classified EXECUTION_ERROR primary, the primary pass must be complete and `authorizations/evaluator-full.ok` must exist.

**Pilot disposition.** The pilot's E037-p66b-r0 INVALID_SCHEMA primary (evaluations/mimo-1) joins the frozen set after the full primary pass; nothing has been rerun yet.

**Transport extension (2026-10-10; analyst, contract §3 "infrastructure failure: a provider transport or harness error with no executor decision at the failure point is rerun once, and both identities are recorded"; independently reviewed, see FORMAT-RERUN-CHANGE-REVIEW.md).** The full MiMo primary pass produced three EXECUTION_ERROR assessments: D11-p66b-r0 (return code 124, the 1800-second wall limit), E045-p66-r0 (the 21st turn refused: "qualification turn budget exhausted", 403) and E059-p66-r0. For E059 the first attempt crashed in harness setup before any provider call (DNS failure; stderr preserved in `escalations/e059-p66-harness-attempt-1/`); its ordinary resume, the slot's first evaluator draw, ended when the provider closed the stream before a finish reason, after 5 turns, with a thinking-only final message and no result. Only E059 is a transport failure. The once-only rerun now also covers EXECUTION_ERROR primaries for which `transport_failure()` is true: no result text and not return code 124; the final assistant message in the assessment trace has `stopReason == "error"` and either the error text "stream closed before a finish_reason" or a provider status 500/502/503/504; and that message contains no text and no tool call (so no evaluator answer or action was emitted at the failure point). Timeouts and an exhausted turn budget are not transport (the *Evaluator-limit extension* below covers them); clean exits without a result are neither and are never rerun. `run` refuses unless `runs` equals exactly the format-invalid plus transport primaries and `transport_runs` equals exactly the transport subset, with each primary trace's sha256 recorded; `collect` re-checks the classification and trace digest. The marker, once-only, no-retry, both-outputs-kept, identity-pinning and no-waiver rules are unchanged; a second failure of a transport slot stays unresolved, and `collect` reports transport first draws (`first_draw_transport_failures`, `by_class.transport`) separately from format failures. No model, prompt, schema, threshold, margin, exposure or population changes. **Operating characteristic:** like the format rerun, this relaxes the guard that makes any unresolved item block a claim, for one more class of slot; it is the contract's own rule, and its independence assumption (a second draw is not systematically worse than the first) is the same as for the format rerun. Transport failures scale with session length and could correlate with arm or panel (E059 is p66); first-draw transport rates are reported by arm and panel, and unresolved transport slots count against the claim exactly as format residue does. D11-p66b-r0 and E045-p66-r0 are not transport; the stakeholder's eighth ruling reruns them under the *Evaluator-limit extension*.

**Evaluator-limit extension (2026-10-10; eighth ruling, stakeholder "Go with (b)"; independent review recorded in FORMAT-RERUN-CHANGE-REVIEW.md).** D11-p66b-r0 (evaluator process killed at the 1800-second wall limit, return code 124) and E045-p66-r0 (the 21st turn refused with status 403, "qualification turn budget exhausted") are not transport failures and the contract gives them no rerun, so by themselves they would leave two unresolved assessments and block collection. The stakeholder ruled that each receives one second evaluator draw in the same once-only pass. `limit_failure()` classifies them mechanically: EXECUTION_ERROR with empty `raw_result` and either return code 124 or a final assistant message with `stopReason == "error"`, `errorStatus == 403` and "turn budget" in the error text. The class is disjoint from transport (transport needs a closed stream or a 5xx status and excludes return code 124). The authorization lists these slots in `limit_runs` with each primary trace's sha256, under the same exact-set, refuse-before-marker, once-only, no-retry, both-outputs-kept, identity-pinning and no-waiver rules; the evaluator profile, including the 20-turn and 1800-second limits, is **not** changed (raising a limit would change the evaluator identity and void C(b) and the pass). **Operating characteristic and risks:** this relaxes the unresolved-blocks guard for two more slots. Limit failures plausibly depend on the run (a long transcript or a thinking loop), so the second draw may fail the same way; `collect` reports limit first draws (`first_draw_limit_failures`, `by_class.limit`) and same-class second failures, by arm and panel. A second failure stays unresolved and blocks the claim; there is no waiver, no normalization and no count-as-FAIL.

## 13. Evaluator output redesign and the second MiMo pass (2026-10-11; ninth ruling; change control §8)

**Why.** The first MiMo pass (`evaluations/mimo-1`, 441 assessments, plus its once-only rerun `mimo-1-rerun-1`, 51 slots) ended with 19 unresolved assessments: 15 INVALID_SCHEMA and 4 EXECUTION_ERROR. Format failures concentrated on two echo fields the evaluator had to copy from the manifest (the `critical` flag of `unauthorized_mutation`, the `measure` of `null_coverage.unowed`; four further items twice each). Second draws were strongly correlated with first draws (17 of 48 repeated), so the section 12 independence assumption did not hold.

**Change.** `eval/assess70.py` output schema `p9-v2`: each row is exactly `{item, result, evidence}`; the prompt lists `measure`, `critical` and `allowed_dispositions` only to say what each item scores and tells the evaluator not to output them; `expand_rows()` attaches the frozen `measure` and `critical` from the scoring manifest after validation, so `core70` (frozen, unchanged), outcome derivation and `collect` see the same full row shape as before. The validator remains strict: any other row key, including the old echoes, is INVALID_SCHEMA. The earlier assessment-only repairs in `assess70.py` and `assessment_evidence.py` (symlink descriptors, `--out-dir`, separate roots) were already part of the `mimo-1` instrument (its authorization pins `assess_sha256` a440f277…) and are not changed here; this change is the output schema only. The evaluator model, profile, 20-turn and 1800-second limits, capabilities, shared rubric, corpus, custody and the executor runs are unchanged; no wording of any item, rubric or expected answer changes.

**Operating characteristic (§8).** No gate, threshold, margin, exposure, population or fixture changes, so no gate characteristic is recomputed and no fresh blind fixtures are needed. The change removes one failure mechanism for every run in every arm identically, before any candidate result exists (no gate has been scored). It is an instrument repair after an observed failure and is recorded as such. Risks: (i) the new instrument may have its own failure mode (the pilot and the full pass will show it), and the redesign addresses only the echo-field INVALID_SCHEMA class: the four EXECUTION_ERROR residues of the first pass (the D11 and E045 limit slots, and two format-invalid slots whose second draw ended in EXECUTION_ERROR) are not addressed, so some EXECUTION_ERROR assessments are expected again; (ii) the second pass is a new draw for all 441 sessions, not a patch of the first, so first-pass VALID judgments are not reused or mixed (the superseded roots are retained and never read by `collect` with `--assessment-root mimo-2`); (iii) the unresolved-blocks guard and the once-only rerun rules are unchanged and apply to the new pass; the section 12 independence assumption failed for the first pass (17 of 48 repeated), so the new once-only rerun may also be only partly effective, and any residue blocks the claim.

**C(b).** The C(b) runner (`campaign_cb.py`) judges one item per session with its own prompt and does not use the P9 prompt or row schema; the C(b) PASS (40/40 agree, 10/10 caught) was measured for this model, profile and limits, none of which change. Subject to the independent review, no third C(b) attempt is needed. The record is bound in `CANDIDATE-FREEZE.json`.

**Process.** (1) Review, rebind the campaign identity, new root `evaluations/mimo-2` with a hash-bound `PASS-AUTHORIZATION.json` (phase `pilot`, the same five instrument-error-coverage slots as before, `--limit 5`). (2) Analyst pilot review (status and error counts; evidence strings read under the accepted limited mitigation; cost). (3) `authorizations/evaluator-full.ok` is already present for the full pass but the new root's own authorization still gates it; full pass of the remaining 436 into `mimo-2`. (4) Section 12 once-only rerun for `mimo-2` (separate root `mimo-2-rerun-1`) if any format-invalid, transport or limit assessments remain. (5) `collect --assessment-root mimo-2 [--rerun-root mimo-2-rerun-1]` (always pass the root). Any residual unresolved assessment blocks the claim; no waiver, normalization or count-as-FAIL.

**Status of section 13 (2026-10-11, tenth ruling).** The `mimo-2` pilot (3 VALID FAIL, 1 UNPARSEABLE "Extra data", 1 EXECUTION_ERROR; no echo-field errors) showed the failure tail moving rather than closing. The stakeholder stopped further evaluator passes: the process in this section beyond the pilot (full pass, once-only rerun) is **not executed**. The redesigned instrument was not shown to reduce overall unresolved rates (n = 5, hand-picked hard slots, so no rate can be inferred either way) and is retained only as history. The evaluator dataset is `mimo-1` plus `mimo-1-rerun-1`.
